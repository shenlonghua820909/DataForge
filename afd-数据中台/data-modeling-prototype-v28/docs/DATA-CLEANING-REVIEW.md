> ② **任务配置改动不触发重算、不进撤销栈** —— `applyTaskField` / `toggleDep` 只写 `TASK` 再 `renderConfig()`，而写入模式、分区字段、目标表都直接决定生成的 SQL，等于「改了看不见」；
> ③ **派生列的提取正则被跨表照搬** —— 提取式正则（`^LN(\d{8})` 只认借阅流水号）是原字段专有形态，字段按角色换成 `return_id` 后照搬会在不报错的情况下整列派生出 `NULL`，现改为「需人工确认」。

## 一、结论

| 维度 | 评价 | 说明 |
|------|------|------|
| **交互范式** | ✅ 方向正确 | 「步骤化流水线 + 逐步回放预览 + 单元格差异高亮」正是 Trifacta / DataWorks 的主流范式，比大多数原型做得实 |
| **规则引擎** | ⚠️ 真实但只读 | 6 个步骤的 `run()` 是真跑（预览表逐格计算），但**只有 3 个步骤的配置项真正生效** |
| **配置完备度** | ❌ 演示级 | 无法**新增**规则，只能微调预置项；`clean` 步配置纯装饰；`date` 步完全只读 |
| **指标可信度** | ❌ 4 处自相矛盾 | 同一屏内「1 行含失败字段」与「✓ 0 行」并存；顶栏永远显示"已通过质量校验" |
| **SQL 闭环** | ❌ 不闭环 | 生成 SQL **有语法错误无法执行**；含空值归一、质量校验两项规则完全未落地；方言混用 |
| **能力边界** | ❌ 单表 | 全链路只支持单表清洗，无 JOIN / Lookup / 聚合 / 窗口 / 脱敏——**撑不起 DWD 宽表**（本项目 DWD 定义含宽表） |
| **规模化** | ❌ 缺失 | 12 行采样冒充全量；无全量试跑、无调度/依赖/增量策略、无版本与回滚、无多表批处理 |

**一句话**：这套页面作为"给客户讲清楚 ODS→DWD 怎么清洗"的演示已经很能打；但要作为交付给客户的**生产级配置界面**，还差一轮"把假交互做真 + 补 DWD 宽表能力 + 修 SQL 生成"的改造。

## 二、已经做好、建议保留的部分

1. **逐步回放预览**：`outputOf(stepId)` 缓存每步输出，点任意步骤即可看该步结果，等价于 DataWorks 的"运行到当前节点"。做法正确，务必保留。
2. **单元格级差异高亮**：`is-changed`（黄绿底 + ⇢）、`is-newval`（蓝底）、`title` 悬浮显示原始值、"仅看发生变化的单元格"——这是整页最有价值的交互，对齐 Trifacta 的核心体验。
3. **智能探测**：`probeFields()` 对原始采样做格式统计并按字段打 chip（`loan_id → 3 组重复键`、`reader_id → 前后空格`、`fine_amt → 货币符号/千分位`），是真实计算而非写死，思路同 DataLeap 的智能识别。
4. **日期多格式归一**：4 种格式（`YYYY/MM/DD`、`DD-MM-YYYY`、`YYYYMMDD`、`YYYY-M-D`）真实实现，失败值单独隔离计数。
5. **失败留痕**：失败字段写入 `__fail` 并保留原始值，可 CSV 导出回源核查——"脏数据不静默丢弃"的意识是对的。
6. **去重语义正确**：`ROW_NUMBER() OVER (PARTITION BY ... ORDER BY sync_time DESC)`，JS 实现与 SQL 语义一致，且去重键/保留策略可切换。
7. **停用步骤真的重跑**：`toggleStep()` 内调 `executePipeline()` 重算，避免读到旧缓存——细节到位。
8. **规则模板库**：把整套流水线配置沉淀为模板，概念正确（对标 DataWorks 的解决方案/同步模板）。
9. **分层语义标注清晰**：`SOURCE · ODS 原始层` → `TARGET · DWD 明细层`，贯穿顶栏面包屑、流水线首尾节点与 SQL 注释。

## 三、缺陷清单

### P0 — 必须修（功能说谎 / 产物不可用）

| # | 问题 | 证据 | 影响 |
|---|------|------|------|
| P0-1 | **生成的 SQL 语法错误，无法执行** | `genSQL()` 用 `selectLines.join(',\n')`，而仅重命名的列会追加行内注释 `-- 原 reader_id`（L650）；逗号被拼到注释之后，变成 `TRIM(reader_id) AS reader_no  -- 原 reader_id,`，**逗号被注释吞掉** | 客户复制 SQL 到 Hive/MySQL 直接报语法错误。这是交付现场最致命的一种 |
| P0-2 | **同一屏内质量结论自相矛盾** | `executePipeline()` 只透传 `{step, rows, stat, removed}`（L371），**丢掉了 `quality.run()` 返回的 `failedCount`**（L338）；`renderConfig()` 因此取到 `undefined → 0` | 面板顶部提示"1 行含失败字段"，下方"类型转换 / 日期解析失败"却显示"✓ 0 行"。用户无法判断该不该导出失败行 |
| P0-3 | **顶栏"✓ 已通过质量校验"是写死的静态文案** | L163，无 `id`、无任何 JS 引用；即使存在失败行也永远绿色 | 质量门禁形同虚设，误导用户认为可以直接上线 |
| P0-4 | **「转换失败策略」三个选项点了不生效** | `cast.run()` 从不读 `config.onFail`（`run.toString()` 校验 `onFail` → `false`，L272-291）；`changeOnFail()` 既不重跑流水线也不重渲染（L773）；三个 radio 还都缺 `value` 属性（L566） | 选"填默认值（0）"或"丢弃该行"，预览与 SQL 完全不变。这是"假配置"的典型 |
| P0-5 | **「字段清理」步骤的配置是纯装饰** | 两个复选框无 `onchange`（L595-596），且整个步骤**没有 `config` 对象**（运行时断言 → `null`）；`clean.run()` 不读任何配置（L249-265） | 用户取消勾选 TRIM 或空值归一，毫无作用 |
| P0-6 | **「🤖 恢复推荐」是空操作** | L614：`onclick="DF.app.toast('已恢复智能推荐规则','success')"` —— 只弹 toast，不恢复任何配置 | 按钮在骗人，用户以为规则回滚了 |

### P1 — 能力缺失（对标大厂的主要差距）

| # | 缺失能力 | 大厂对照 | 对本项目的具体影响 |
|---|----------|----------|--------------------|
| P1-1 | **只能改预置规则，不能新增** | DataWorks/DataLeap 可任意加算子 | `map` 步的「字段重命名」只渲染已有映射，**没有"+ 添加"入口**（L539）；`cast` 步同理只能改那 2 列（L553）。新表接入时无法配置 |
| P1-2 | **无多表 JOIN / Lookup** | 各家的 Join 算子 | 本项目 DWD 层定义**包含宽表**，宽表必然要多表关联。当前流水线固定 `map→clean→cast→date→dedup→quality` 六步，**完全没有关联能力**，宽表建模只能绕回 `14-new-table-wizard` 手工建 |
| P1-3 | **无聚合 / 窗口 / 列拆分合并 / 正则提取** | 基础算子集 | 无法在清洗阶段做"按证号汇总借阅次数"、"从题名提取卷册"这类常见加工 |
| P1-4 | **无脱敏 / 加解密 / 码值映射** | DataWorks 数据保护伞、字段级脱敏 | 读者证号、身份证号进入 DWD 前无脱敏手段；`circ_status` 的 `Y/N` 枚举也未做码值翻译（本应映射为"在借/已还"） |
| P1-5 | **空值策略只有"置 NULL"一种** | 可配默认值 / 分流 / 补全 | 与 P0-4 同源；且 dedup/date 步各自硬编码"失败置 NULL"，无统一策略 |
| P1-6 | **质量规则不可配置，仅为只读展示** | DataWorks DQC：可加规则、设阈值、配告警与阻断 | `quality` 步 3 行结论里 2 行是静态字符串（L603-605），无法新增规则、无阈值、无"不达标阻断写入" |
| P1-7 | **无脏数据分流表** | DataWorks 脏数据表 / 死信队列 | 失败行"置 NULL 写入 DWD + 导出 CSV"，但 CSV 是手工下载，未落成可追溯的隔离表。DWD 里出现 NULL 却无从知道当初的原值在库里哪张表 |
| P1-8 | **生成 SQL 与可视化配置不闭环** | 配置即 SQL，两向一致 | ①`clean` 步的空值归一（`''`/`'NULL'`/`'/'`→NULL）**完全没进 SQL**（`NULLIF` 检测 → `false`）；②`quality` 步没进 SQL；③`sync_time` **被重复 SELECT**（`TRIM(sync_time) AS sync_time` 后又追加 `,sync_time`，L668） |
| P1-9 | **SQL 方言混用** | 需选方言 | 同时产出 Hive 关键字（`INSERT OVERWRITE` / `PARTITION`）与 MySQL 函数（`STR_TO_DATE` / `DATE_FORMAT` / `REGEXP`），**在任一引擎都跑不起来** |
| P1-10 | **单表硬编码** | 多表批处理 | 源表 `ods_circ_loan_sync` 写死在 HTML 里，无下表选择器（运行时断言：`.src-panel select` → 0）。同类源表无法批量套规则 |
| P1-11 | **无全量试跑 / 采样与生产混淆** | 试跑与生产隔离 | 左侧写"昨日全量 1,284,730 行"，预览却是**12 行采样**，而预览区**没有任何"采样"标注**；质量分是拿 12 行算出来的，却看起来像整表的分数 |
| P1-12 | **日期歧义格式静默处理** | 歧义需人工确认 | `08-09-2026` 被直接判为 `DD-MM-YYYY` → `2026-09-08`。若源系统实为 `MM-DD-YYYY`，结果错得很安静，无确认弹窗 |

## 五、优化建议（按优先级分档）

### 第 1 档 · 把假交互做真（改动小、收益最大，建议先做）
1. 修 P0-1：`selectLines` 改为先 `join(',\n')` 再让注释独立成行（把 `-- 原 src` 移到该行逗号之前，或注释统一放行尾前）。
2. 修 P0-2／P0-3：`executePipeline` 透传 `failedCount`；顶栏校验态改为按失败行数动态渲染（0 行→绿，>0 行→橙）。
3. 修 P0-4／P0-5：`cast.run()` 与 `clean.run()` 真正读取配置；`changeOnFail` 补 `value` 属性并触发重跑；`clean` 步补 `config{trim, nullNormalize}`。
4. 修 P0-6：`恢复推荐` 改为真正回滚该步骤到推荐配置。
5. 修 P2-5／P2-6／P2-7：日期格式清单、探测汇总、质量分全部改为由 `probeFields()` / `executePipeline()` 实时计算。

### 第 2 档 · 补齐 DWD 宽表能力（决定这套页面能不能支撑真实交付）
6. 新增 **JOIN / Lookup 步骤**：支持源表 + 维表按主键关联，字段勾选进入结果集（这是 DWD 宽表的硬需求）。

### 第 3 档 · 工程化与规模化 ✅ 已完成
11. ✅ **SQL 闭环**：`clean` 的空值归一（`UPPER(TRIM(…))` + 占位清单 `THEN NULL ELSE`）与质量校验全部落到 SQL；加了**方言选择器**（Hive / Spark / MySQL / Doris，四种引擎的覆盖语义、日期函数与格式串风格、正则算子与组提取、长度/分词函数、CAST 目标类型、调度变量与日期算术全部按真实差异生成）；SQL 页签加了**复制**与**下载 .sql**（文件名 `任务代码.方言.sql`）。修 P1-8／P1-9／P2-2。
    - 生成的 SQL 分三段：`① 质量门禁（DQC 断言）` → `② 主写入 → <目标表>` → `③ 脏数据分流 → <目标表>_dirty`。
    - 无法安全改写的地方**显式告警而非静默降级**：正则含分组内部歧义时打 `-- ⚠ 方言差异`（例：MySQL 无 `REGEXP_EXTRACT(…, group)`，能推导则改写为 `REGEXP_SUBSTR`，推不出就说明按整段匹配）。

13. ✅ **脏数据分流表**：失败行写入 `<目标表>_dirty` 隔离表，按「字段 × 原因」拆分 `UNION ALL` 分支，带 `fail_field` / `fail_reason` / `fail_raw_value` / `quarantine_time` 审计列；面板写明血缘 `源表 → _dirty → 质量看板 / 人工复洗队列 → 回灌目标表`；隔离表**恒为追加写入**，不随主表写入模式覆盖（否则会清掉尚未复洗的台账）。
14. ✅ **采样与生产分离**：预览区徽标显式标注「采样 12 行 · 不代表全量」且可点开口径说明（讲清"为什么阈值不能拿采样算"）；顶栏提供 **⚡ 全量试跑** 入口，按模板等比例放大并**真实跑完全部步骤**、逐步进度 + 每步耗时、结果面板给出全量口径的质量分/失败格/脏数据行；行数上限 `FULL_LIMIT = 1,000,000` 保护，超限直接拒绝执行；预览表只渲染前 `PREVIEW_CAP = 200` 行但指标按全量统计，可一键切回采样。
    - 质量分已改为**比率加权**（`100 − Σ(问题比率 × 权重)`，权重合计 100），因此 12 行采样与 20 万行全量的得分可直接比对；旧口径按绝对条数扣分，同一份脏数据比例下 2 万行就会把分数打到 0（指标失去意义）。
