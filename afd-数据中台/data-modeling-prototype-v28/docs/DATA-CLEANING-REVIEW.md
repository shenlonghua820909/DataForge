| **指标可信度** | ❌ 4 处自相矛盾 | 同一屏内「1 行含失败字段」与「✓ 0 行」并存；顶栏永远显示"已通过质量校验" |
| **SQL 闭环** | ❌ 不闭环 | 生成 SQL **有语法错误无法执行**；含空值归一、质量校验两项规则完全未落地；方言混用 |
| **能力边界** | ❌ 单表 | 全链路只支持单表清洗，无 JOIN / Lookup / 聚合 / 窗口 / 脱敏——**撑不起 DWD 宽表**（本项目 DWD 定义含宽表） |
| **规模化** | ❌ 缺失 | 12 行采样冒充全量；无全量试跑、无调度/依赖/增量策略、无版本与回滚、无多表批处理 |

**一句话**：这套页面作为"给客户讲清楚 ODS→DWD 怎么清洗"的演示已经很能打；但要作为交付给客户的**生产级配置界面**，还差一轮"把假交互做真 + 补 DWD 宽表能力 + 修 SQL 生成"的改造。

## 二、已经做好、建议保留的部分

1. **逐步回放预览**：`outputOf(stepId)` 缓存每步输出，点任意步骤即可看该步结果，等价于 DataWorks 的"运行到当前节点"。做法正确，务必保留。
2. **单元格级差异高亮**：`is-changed`（黄绿底 + ⇢）、`is-newval`（蓝底）、`title` 悬浮显示原始值、"仅看发生变化的单元格"——这是整页最有价值的交互，对齐 Trifacta 的核心体验。
3. **智能探测**：`probeFields()` 对原始采样做格式统计并按字段打 chip（`loan_id → 3 组重复键`、`reader_id → 前后空格`、`fine_amt → 货币符号/千分位`），是真实计算而非写死，思路同 DataLeap 的智能识别。
4. **日期多格式归一**：4 种格式（`YYYY/MM/DD`、`DD-MM-YYYY`、`YYYYMMDD`、`YYYY-M-D`）真实实现，失败值单独隔离计数。
5. **失败留痕**：失败字段写入 `__fail` 并保留原始值，可 CSV 导出回源核查——"脏数据不静默丢弃"的意识是对的。
6. **去重语义正确**：`ROW_NUMBER() OVER (PARTITION BY ... ORDER BY sync_time DESC)`，JS 实现与 SQL 语义一致，且去重键/保留策略可切换。
7. **停用步骤真的重跑**：`toggleStep()` 内调 `executePipeline()` 重算，避免读到旧缓存——细节到位。
8. **规则模板库**：把整套流水线配置沉淀为模板，概念正确（对标 DataWorks 的解决方案/同步模板）。
9. **分层语义标注清晰**：`SOURCE · ODS 原始层` → `TARGET · DWD 明细层`，贯穿顶栏面包屑、流水线首尾节点与 SQL 注释。

## 五、优化建议（按优先级分档）

### 第 1 档 · 把假交互做真（改动小、收益最大，建议先做）
1. 修 P0-1：`selectLines` 改为先 `join(',\n')` 再让注释独立成行（把 `-- 原 src` 移到该行逗号之前，或注释统一放行尾前）。
2. 修 P0-2／P0-3：`executePipeline` 透传 `failedCount`；顶栏校验态改为按失败行数动态渲染（0 行→绿，>0 行→橙）。
3. 修 P0-4／P0-5：`cast.run()` 与 `clean.run()` 真正读取配置；`changeOnFail` 补 `value` 属性并触发重跑；`clean` 步补 `config{trim, nullNormalize}`。
4. 修 P0-6：`恢复推荐` 改为真正回滚该步骤到推荐配置。
5. 修 P2-5／P2-6／P2-7：日期格式清单、探测汇总、质量分全部改为由 `probeFields()` / `executePipeline()` 实时计算。

### 第 2 档 · 补齐 DWD 宽表能力（决定这套页面能不能支撑真实交付）
6. 新增 **JOIN / Lookup 步骤**：支持源表 + 维表按主键关联，字段勾选进入结果集（这是 DWD 宽表的硬需求）。
7. 新增 **码值映射步骤**：`Y/N → 在借/已还` 之类的枚举翻译，规则可导入。
8. 新增 **脱敏步骤**：证号/身份证哈希或掩码，支持"脱敏后仍可关联"（保留哈希列）。
9. 新增 **列拆分 / 合并 / 正则提取** 步骤。
10. **支持新增规则**：`map` / `cast` 等步骤补"+ 添加字段"入口，并把字段列表做成可勾选的规则入口（修 P1-1 + P2-4）。

### 第 3 档 · 工程化与规模化 ✅ 已完成
11. ✅ **SQL 闭环**：`clean` 的空值归一（`UPPER(TRIM(…))` + 占位清单 `THEN NULL ELSE`）与质量校验全部落到 SQL；加了**方言选择器**（Hive / Spark / MySQL / Doris，四种引擎的覆盖语义、日期函数与格式串风格、正则算子与组提取、长度/分词函数、CAST 目标类型、调度变量与日期算术全部按真实差异生成）；SQL 页签加了**复制**与**下载 .sql**（文件名 `任务代码.方言.sql`）。修 P1-8／P1-9／P2-2。
    - 生成的 SQL 分三段：`① 质量门禁（DQC 断言）` → `② 主写入 → <目标表>` → `③ 脏数据分流 → <目标表>_dirty`。
    - 无法安全改写的地方**显式告警而非静默降级**：正则含分组内部歧义时打 `-- ⚠ 方言差异`（例：MySQL 无 `REGEXP_EXTRACT(…, group)`，能推导则改写为 `REGEXP_SUBSTR`，推不出就说明按整段匹配）。
12. ✅ **质量规则可配置化**：规则列表（启停 / 类型 / 字段 / 参数 / 阈值 / 动作 / 删除）+ **＋ 添加质量规则**；6 类 DQC 模板（唯一性 / 非空 / 值域白名单 / 数值区间 / 正则 / 自定义算子）；不达标动作三态 **阻断 / 告警 / 继续**；每条规则实时显示实测通过率与违规样本；阈值以「通过率 %」表达，`block` 级未达标即判定任务失败、不写目标表并阻断下游。规则一并落到 SQL 的 `①` 段（`rule_name` / `on_fail` / `threshold_pct` + 违规数表达式）。
