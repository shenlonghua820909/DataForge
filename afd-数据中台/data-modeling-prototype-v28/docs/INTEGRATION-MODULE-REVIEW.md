# 数据集成模块（02b + 02c）功能闭环与对标核查

> 评估对象（**核查当时**的行数）：`pages/02b-data-sources.html`（2,179 行）、`pages/02c-ods-tables.html`（568 行）、`assets/integration-data.js`（453 行）、`assets/file-parse.js`（485 行）
> 补齐后：02b **3,041 行** · 02c **591 行** · `integration-data.js` **928 行** · `integration.css` 314 行（落地明细见 [§七](#七落地结果2026-09-21)）
> 评估口径：**产品原型**。Mock 数据可接受，核查两件事 —— 功能逻辑是否闭环、操作是否合理且对标大厂数据中台
> 核查方式：逐段读码 + 交互入口穷举（`onclick` 全量提取）+ 状态机可达性分析
> 时点：2026-09-21

## 结论

**部分闭环，断点在模块正中央。**

做得很扎实的两块：**数据源管理**（4 步向导 + 增删改 + 影响面确认 + 撤销）与 **ODS 表管理**（双视图 + 四维筛选 + 详情抽屉 + 单表/批量同步 + 未纳管表纳管 + 导出 + URL 参数闭环）。这两块的信息架构与操作路径，是按大厂产品的样子搭的。

**断在中间的「同步任务」这一层。** 模块里已经有了它的位置 —— 抽屉里有「同步任务」页签，空态里放了「新建同步任务」按钮，但它们点下去只弹一句 `已打开同步任务向导（原型示意）`，**没有向导、没有字段映射、没有通道控制、没有调度配置、没有任务实例**。

> ✅ **2026-09-21 已补齐。** 第五节 P0 / P1 / P2 与「顺带清理」全部落地并通过回归（七套断言 668 条 + 数据集成行为冒烟 53 条，全绿）。上文「断点」描述保留为**问题记录**，落地结果与证据见 [§七](#七落地结果2026-09-21)。

于是整条链路是「跳过去」的：库表扫描之后，直接就到了「ODS 表已经在库里」的状态，中间"这张表怎么同步过来"的那一环没有界面承载。

## 二、闭环核查：断在哪一环

按大厂数据集成模块的标准链路逐环核对：

| # | 环节 | 状态 | 说明 |
|---|---|---|---|
| 1 | 数据源接入 | 通 | 4 步向导，文件类真解析（`file-parse.js` 自解 ZIP） |
| 2 | 连接测试 | 通（结果模拟） | 有 UI 与两种校验口径，无真实请求 |
| 3 | 源端库表扫描 | 通 | 「库表结构」页签，含源端未纳管表 |
| 4 | **同步任务配置** | **断** | **「新建同步任务」按钮只弹 toast，无向导** |
| 5 | **调度配置** | **断** | `freq` 字段只作展示，无调度配置界面 |
| 6 | **运行与监控** | **断** | 「运行监控」页签是写死的事件流，与实际同步状态无关 |
| 7 | 数据落 ODS | 通 | 表级状态机 + 批量同步（结果模拟） |
| 8 | 交给数据清洗 | 通 | 「去清洗」带 `?table=` 跳转，清洗页接住 |

**第 4、5、6 环缺失，其中第 4 环是根** —— 5 和 6 依附于"任务"这个实体，任务不存在，调度与监控就无处挂载。

### 断点的直接证据

```
pages/02b-data-sources.html:1009
  <button onclick="DF.app.toast('已打开同步任务向导（原型示意）','info')">新建同步任务</button>

pages/02b-data-sources.html:1277
  <button onclick="closeDsWizard(); DF.app.toast('已打开同步任务向导（原型示意）','info')">立即创建同步任务</button>
```

两处入口都只有提示，没有流程。**入口画了、流程没做** —— 这是原型打磨阶段最容易留在库里、也最容易被客户点到的缝。

## 四、三处内部不一致（打磨时会被点到）

### 4.1 异常态只摆给人看，用户操作造不出来

`STATUS_META` 定义了 6 态，02c 的筛选器也给了「同步失败」「结构变更待确认」两个筛选项，mock 数据里也确实各有一条（`failed` 2 条、`schema` 1 条）—— 所以筛选**不是空集**，看上去是完整的。

问题在**可达性**：**没有任何代码路径能把这些状态产生出来**。

- `runSync(id)` 只会 `syncing → synced`，从不落到 `failed`
- `failed` 表可以**离开**这个状态（`syncOne()` 的过滤是 `status !== 'synced' && status !== 'syncing'`，所以点「立即同步」能把它治好 → `synced`），但**无法进入**
- `schema`（结构变更待确认）连"离开"的路径都没有

失败态的文案其实已经写好了 —— 两条 mock 数据的 note 就是失败原因（「解析失败：表头缺失，需指定表头行号后重传」「认证失败（API Key 已过期），需在数据源里更新后重试」）。**有失败态的定义、有失败原因的文案，但没有让用户碰到失败的路径** —— 比如让某次同步真的失败、给出日志与重试按钮。客户评审时问一句「同步失败了怎么办」，目前答不上来。

### 4.2 `.sync-task` 是死样式

```
pages/02b-data-sources.html:141-143
  .sync-task { ... }
  .sync-task__name { ... }
  .sync-task__meta { ... }
```

三个类定义了「同步任务条目」的样式，但**没有任何 JS 渲染 `class="sync-task"` 的元素**（全仓 0 处）。这是「同步任务列表」曾经计划要做的痕迹。

### 4.3 「运行监控」与实际状态脱钩

抽屉第 4 个页签「运行监控」里的事件流是**写死的四条**：

```
14:32:08  同步任务 ds-001 启动
14:32:14  连接成功，schema 校验通过
14:35:22  已同步 8,932 行（耗时 3 分钟）
14:38:50  检测到 1 张新表 circulation_log_v2
```

而用户点「立即同步」时，02c 里的状态**真的会变**（`pending → syncing → synced`）。两处对不上：状态在动、日志不动、连接池数字不动、折线图不动。

**这是"功能不闭环"最容易被感知的一条** —— 用户点完同步，去"运行监控"看，会发现没有任何反应。

## 五、补齐建议

### P0：同步任务配置向导（补上断掉的第 4 环）

一个 5 步向导，与数据源向导同一套交互语言：

1. **选择源表** —— 从「库表结构」里选（勾选多张 = 批量任务）
2. **目标表** —— 默认按规则生成 `ods_<源表>`，可改
3. **字段映射** —— 源字段 → 目标字段，含类型映射、默认值、是否同步；给「全选 / 按名匹配」快捷操作
4. **同步策略** —— 全量覆盖 / 增量追加（选增量字段）；写入模式
5. **调度配置** —— 周期（日/小时/手动）+ 调度时间 + 并发 + 脏数据阈值

完成 → 生成一条**任务记录**，落到该数据源下的任务列表。

### P1：任务与实例

1. 抽屉「同步任务」页签改为**任务列表**（当前是表清单派生统计）—— 复用已定义的 `.sync-task` 样式
2. 任务详情：最近实例、状态、耗时、行数、脏数据条数
3. 「立即运行」→ 实例状态真实流转（`等待 → 运行中 → 成功/失败`）
4. 「运行监控」页签**接真数据**：事件流由实例状态派生，不再写死
5. 失败可达：允许任务失败（如"目标表不存在"），给失败详情 + 重试

### P2：向大厂看齐的进阶项

1. 字段映射的类型自动映射与冲突提示
2. 整库同步方案（一次配置、批量生成 N 张表的任务）
3. 数据源复制
4. 资源组 / 网络配置（原型里可做成只读展示）
5. 结构变更检测闭环：`schema` 状态可达 → 任务影响面 → 确认后继续

### 顺带清理

- 删掉 `.sync-task__name` / `.sync-task__meta` 死样式，或在 P1 里用起来
- 让 `failed` / `schema` 可达，或在筛选器里暂时摘掉（**留着筛不出东西的筛选项比没有更伤**）

## 六、一句话回答

**数据集成模块的「两端」做得相当完整（数据源管理、ODS 表管理），断的是正中间的「同步任务」层** —— 而这一层恰好是大厂数据集成模块的主体（任务向导、字段映射、通道控制、调度配置、任务实例）。补齐它，模块就从"两个漂亮的列表页"变成"一条走得通的链路"。

## 七、落地结果（2026-09-21）

> 依据：本节所有结论都有**可复跑的验证**兜底 —— 七套运行时断言（合计 **668** 条）+ 一份数据集成行为冒烟（**53** 条）。跑法见 §7.5。

### 7.1 P0 —— 同步任务配置向导（断掉的那一环接上了）

实现位置：`pages/02b-data-sources.html` 的「同步任务向导」整块（`openSyncWizard()` / `renderSyncWizard()` / `syncWzStep1Html()` ~ `syncWzStep5Html()` / `syncWzFinish()`）。

| 步骤 | 落地内容 | 关键取舍 |
|---|---|---|
| ① 选择源表 | 从「库表结构」取名下**全部**源端表，已纳管的排前、未纳管的排后并注明「建任务时会一起纳入同步清单」 | 一张表**同时只能属于一条任务**：已被别的任务占用的行置灰、勾不上（避免一张表两条任务互相覆盖） |
| ② 目标表 | 默认按规则生成 `ods_<源表>`，可逐张改 | 目标名**非法或与同批其它表重名**时拦住不放行，并把违规行标红（见 7.4） |
| ③ 字段映射 | 源字段 → 目标字段，可改名 / 改类型 / 设默认值 / 单独关掉某列；给「全选字段 / 按名匹配（重置）/ 全部不同步」 | 库表类**没有真实 schema**，用与源端表字段数一致的**示例字段**，并在页面上**显式标注「示例字段」** —— 与解析引擎给示例结果打标注同一套规矩，不冒充真 schema |
| ④ 同步策略 | 全量覆盖 / 增量追加（选增量水位字段）；写入模式 overwrite / append / upsert | 选增量但没填字段 → 拦住（否则会整表重跑） |
| ⑤ 调度配置 | 周期（实时 / 分钟 / 小时 / 每天 / 每周 / 每月 / 手动）+ 调度时间 + 并发 + 脏数据阈值 + 失败重试 | 完成页给出确认摘要；结束即**生成 1 条任务记录**并自动跳到该数据源的「同步任务」页签 |

向导刻意沿用「新增数据源」向导的同一套壳子（`.ds-wizard` / stepper / 上一步·下一步），不另起一套交互语言。

### 7.2 P1 —— 任务与实例

- **「同步任务」页签改成真任务列表**（`renderSyncTab()`）：顶部仍是四档 ODS 落地情况（已同步 / 同步中 / 未同步 / 失败待确认），下方是**任务条目**（`.sync-task`：名称 + 运行态胶囊 + 标签 + 来源→目标 + 调度 + 映射字段数 + 最近一次实例）。`.sync-task__name` / `.sync-task__meta` 从死样式变成主力样式。
- **任务详情**（`openTaskDetail()`）：任务配置（任务 ID / 来源数据源 / 调度状态 / 并发与脏数据阈值 / 同步策略 / 创建时间 / 运行环境）、表映射、字段映射（带类型校验结论）、运行实例（开始时间 / 状态 / 耗时 / 写入行数 / 脏数据 / 失败原因）。
- **立即运行 → 实例真实流转**（`runTask()`）：`running → success / failed`，并把所辖 ODS 表状态一起回写（成功→`synced`、失败→`failed`、结构变更→`schema`）。**`runSync()` 已改为委托 `runTask()`**，消灭了「任务列表说失败、ODS 列表说已同步」两套事实。
- **运行监控页签接真数据**（`renderMonitorTab()`）：三个 KPI、近 7 天写入柱状图、事件流**全部由运行实例派生**（`instanceStats()` / `dailyBuckets()` / `recentInstances()`）。原来那段写死的假事件流（固定 14:32:08 / 8,932 行 / `circ_loan_log_v2`）连同假时序图 `renderMiniLineChart()` 一并删除。
- **失败可达**：任务失败**只由 `task.blocker` 触发，绝不随机抽奖** —— 固定 4 条种子任务是阻塞态（解析失败 / 鉴权失败 / 结构变更）。用户点「处理阻塞」→ `clearTaskBlocker()` → 重跑即成功，形成 `失败 → 看原因 → 处理 → 重试 → 成功` 的闭环。连续失败会把调度自动暂停。

### 7.3 P2 —— 向大厂看齐

1. **字段类型自动映射与冲突提示**：`autoMapping()` 产出「按名匹配」映射；`typeConflict()` 给每列结论 —— 数值→字符串判「注意」、**文本→数值判「冲突」并整行标红**、一致则标「一致」。
2. **整库同步**：向导第 1 步「整库同步（全选 N）」一键选中该库所有还能建任务的表，一次配置生成 1 条批量任务（任务条目标「批量 · N 张表」）。
3. **数据源复制**：卡片 / 列表 / 抽屉的「⧉ 复制数据源」→ 复用新增向导、预填连接配置、名字加「（副本）」、**不带 `editId`**（保证走「新建」而不是把原数据源改掉）。
4. **资源组 / 网络配置（只读展示）**：任务详情「运行环境」给出默认资源组 `di-default-resgroup` 与 VPC 专网。
5. **结构变更检测闭环**：`schema` 状态可达（阻塞类型 `schema`）→ 任务详情报「结构变更」影响面 → 「确认变更并继续」→ 重跑落地成功。

### 7.4 顺带清理 + 核查过程中新发现的两个真 bug

- `.sync-task` 全家从死样式转为在用；`.sync-tbl` 全家（旧「把 ODS 表换个表头当任务列表」用的那套）**连根删除**。
- `failed` / `schema` 从"用户造不出来的样子货"变成**可达状态**。
- **设计令牌静默失效（真 bug）**：`design-tokens.css` 每个语义色只有 50/100/500/700 四档，而代码里引用了 `--danger-600`（危险按钮背景）、`--success-600` / `--warning-600`（KPI 图标 stroke）、`--danger-300/400` —— 浏览器会**整条丢弃**这些声明，症状是「危险按钮白底白字、图标不着色」。已在 `assets/integration.css` 的 `:root` 补齐五个档位。
- **`editDs()` / `copyDs()` 落点错误（真 bug）**：两者都调 `openDsWizard(2)`，而该函数内部的 `renderWizard()` 会因为此刻 `wizardData.type` 还是空而**把步骤弹回第 1 步**（`renderWizard()` 的 `if (!meta) { wizardStep = 1; ... }`）。结果是：卡片上点「编辑配置 / 复制数据源」，向导停在「第 1 步 选择类型」，看起来像没生效。已在 `wizardData` 填好后重设落点。
- **向导校验失败不标红（体验缺陷）**：目标表名输入框为了保焦点刻意不重绘，于是「校验不通过」时只弹一条 toast、违规行不变红 —— 用户不知道是哪一张表的问题。已改为**拦截时补一次重绘**，让违规行高亮。
