# ODS 数据清洗页 · 操作手册

> 页面：`pages/15-data-cleaning.html`（本地 `http://127.0.0.1:8000/pages/15-data-cleaning.html`）
> 用途：把客户业务系统同步过来的 **ODS 原始数据**，通过可视化配置清洗成 **DWD 明细层**可用表
> 对标：阿里云 DataWorks（DataStudio 数据集成 + 数据质量 DQC）、字节 DataLeap

---

## 〇、先建立正确的心理模型

这一页不是"填个表单然后提交"，而是**一条流水线 + 一个实时回放器**：

```
ODS 原始表  →  ① 字段映射 → ② 字段清理 → ③ 码值映射 → ④ 类型转换 → ⑤ 日期标准化
            →  ⑥ 数据去重 → ⑦ 多表关联 → ⑧ 列加工 → ⑨ 数据脱敏 → ⑩ 质量校验  →  DWD 明细表
                                                                            ↘ 脏数据隔离表
```

四条贯穿全页的规则，理解了就不会困惑：

| 规则 | 含义 |
|------|------|
| **口径只有一个来源** | 预览表的列头、质量指标的统计口径、生成的 SQL 投影，三处由**同一份列计划**推导，不会互相打架 |
| **改配置 = 立刻重算** | 任何一个配置改动都会重跑整条流水线，预览、质量分、SQL 同步更新；没有"保存后才生效"这回事 |
| **看的是采样** | 左侧采样 12 行用于交互预览；要验证全量口径得点顶栏的「全量试跑」 |
| **失败不静默** | 无法解析的值、无法套用的规则、有歧义的日期，都会显式标注或要求人工确认，不会悄悄变成 NULL |

## 二、标准操作流程（第一次用，按这个顺序走）

### 第 1 步 · 选源表（左栏）

左栏只显示**当前正在编辑的那张表**（卡片上带表名、同类/缺什么、中文名 → 目标表、连接与数据量）。

唤起**切换源表浮层**有两个入口（同一套浮层、同一个快捷键，随便用哪个都行）：

| 入口 | 位置 | 说明 |
|---|---|---|
| **顶栏面包屑里的表名** | 左上角 | `数据集成 / ODS 数据清洗 / ` **`ods_circ_loan_sync ⌄`** —— 带虚线边框的小胶囊，点它就展开。**切表后这里会跟着刷新**，所以它同时也是"我现在在洗哪张表"的常驻指示 |
| **左栏当前表卡片** | 左栏顶部 | 卡片上常驻一行 `点表名切换 ⇧⌘K`，鼠标移上去会提亮 |

不在这两处也能唤起：按 `⇧⌘K`，浮层会贴到面包屑表名下方。

候选**不是**清洗页自己攒的一张清单，而是**和「数据源管理」「ODS 数据表」同一份事实源**（`assets/integration-data.js` 的 `ODS_TABLES`）—— 在数据源页认识的那些表，这里全都找得到：

| 档位 | 张数 | 长什么样 | 点下去会怎样 |
|---|---|---|---|
| **已配清洗任务** | **10** | 青 / 绿徽标 **同类** 或 **缺 X** | 正常切换，中栏流水线 / 预览 / 右栏配置全跟着换 |
| **未配清洗任务** | **19** | 灰色虚线徽标 **未配清洗任务** | **不切表**，弹一条引导 toast 告诉你先去哪建任务 |

浮层按**数据源**分成 **12 组**（`MySQL · 汇文流通`、`Oracle · 汇文 ALEPH`、`MaxCompute · 复旦湖仓`…），组标题右侧报 **「可清洗 / 本组张数」**（`5/9` = 该数据源下有 9 张表、其中 5 张已配清洗任务）。搜索支持 **表名 / 中文名 / 数据源名 / 源端表名 / 字段名**：想找「ALEPH 下面有哪些表」「源库里叫 holding 的表同步成了哪张 ODS」，直接搜那两个字即可。

浮层的高亮行还会显示**切换后果预知**（例如「⚠ 切换后：2 项规则不适用」）—— 先看清代价再切，不必切过去才发现模板套不上。

> **为什么「未配清洗任务」的表也要列出来？**
> 因为"能不能选"和"能不能洗"是两件事。数据源刚接入时，ODS 表已同步、清洗任务还没建（这正是「数据源管理 → 库表结构」抽屉里提示的那个状态）。
> 把它们藏起来，会让人以为"这些表白同步了"；把它们做成可点，又会造成**假切换**（切到一张其实没有任何规则的"当前表"，用户以为自己配好了）。
> 所以这里的取舍是：**列出来 + 显式标注 + 点了就告诉你去哪建任务**。

> 💡 **从「数据源管理 / ODS 数据表」过来更快**：那两个页面里，每张已同步的表都有「**去清洗**」入口，点它会带着这张表的身份跳过来（`15-data-cleaning.html?table=<ods_id>`）。已配清洗任务 → 直接切到那张表；还没配 → 停留在默认表并提示你先去建任务。**不会再出现"点了去清洗、落下来却是另一张表"**。

**10 张表的业务分布**：

| 域 | 表 | 主键形态 | 关键场景 |
|---|---|---|---|
| 流通业务 | ods_circ_loan / return / renew / hold / ill | LN / RT / RN / HD / IL + 8 位 | 借还 → 续 → 约 → 馆际；主键与读者键齐备 |
| 采访业务 | ods_acq_accept | AC + 8 位 | 图书验收（ACQ）；无读者键 |
| 编目业务 | ods_cat_book | BK + 8 位（+ ISBN 13 位） | 图书编目（CAT）；无读者键、无 status |
| 典藏业务 | ods_inv_stocktake | ST + 6 位 | 馆藏盘点（INV）；扫码时间，无 dates 无关读者键 |
| 期刊业务 | ods_per_received | IS + 8 位 | 期刊到刊（PER）；无 status、无读者键 |
| 读者业务 | ods_patron_register | RG + 8 位 | 读者办证；证件类型作为 status，无读者键 |

→ **跨域模板套用**：这 10 张表分属 6 个业务域、语义角色并不齐备（图书域缺 status、典藏域 dates 唯一、读者域双日期但无数值），
所以"一套模板能不能套到另一张表"要看**语义角色**，而不是看表名像不像。

切表后，左栏下方的字段清单和"智能探测"结论会一起刷新。**每次换表都要重看一遍智能探测**，不能沿用上一张表的判断。

> 左栏那张 **「◉ 当前编辑的表」** 卡片，标的**永远是你正在编辑的这一张表**（与中栏预览同源）。

> ⚠ **多表操作不在左栏。** 左栏自 09-15 起**只做单表**：不再有行内复选框，也不再在左栏下半部分渲染「多表字段对照」。
> 要给一批表套同一套规则，走**顶栏「🗂 多表批处理」**（见第 10 步）：在弹窗里勾选目标表、可一键「全选同类表」，
> 它按**语义角色**（而不是表名像不像）判定谁同类、谁缺角色，逐表真实产出指标与 SQL；
> 翻译不了的规则会**显式标为「不适用 / 需人工确认」，绝不静默丢弃**。

### 第 2 步 · 读"智能探测"，定下这次要处理什么（左栏）

左栏下半部分是**字段与智能探测**。每个字段右侧挂着引擎扫出来的问题标签，例如：

| 字段 | 探测到的标签 | 说明 |
|------|--------------|------|
| `loan_id` | `3 组重复键` | 业务主键有重复 → 需要去重 |
| `reader_id` | `前后空格` | 需要 TRIM |
| `loan_date` | `YYYY/MM/DD`、`DD-MM-YYYY`、`YYYYMMDD`、`YYYY-M-D`、`DD-MM-YYYY（歧义）` | 5 种格式混用 → 需要日期标准化 |
| `return_date` | `空值占位`、两种日期格式 | `/` 被当真实值 → 需要空值归一 |
| `borrow_cnt` | `字母混入` | 有 `x1` 这类值 → 转 INT 会失败 |
| `fine_amt` | `货币符号/千分位`、`非数字字符` | 需要剥离 ¥ 与逗号 |
| `circ_status` | `大小写不一致` | `Y` / `y` 混用 → 需要码值映射 |

汇总一句话写在最下面，本次是：**扫描 12 行 × 8 字段，发现 35 处格式问题（10 类）、3 组重复键、5 处空值占位**。

**关键操作：单击任意字段名，页面会自动跳到"负责处理这个字段的那一步"**，并把预览回放到那一步。实测跳转关系：

| 点这个字段 | 跳到哪一步 |
|------------|-----------|
| `reader_id` | 字段清理 |
| `circ_status` | 码值映射 |
| `borrow_cnt`、`fine_amt` | 类型转换 |
| `loan_date` | 日期标准化 |
| `loan_id`、`sync_time` | 数据去重 |

这是**最省事的入口**：不用自己判断该去哪步，引擎已经分配好了。

### 第 3 步 · 逐步骤确认规则（中栏 → 右栏）

在流水线上**点一个步骤节点**，右栏就会出现该步的配置。注意两点：

1. **点步骤同时会改变预览的"回放点"** —— 预览表会显示"回放至 · 日期标准化"，并给出该步执行后的记录数（如去重步显示 `9 行（源表采样 12 行 · 本步减少 3 行）`）。
2. 右栏顶部先看**智能推荐**那一行，它会告诉你这一步当前的实际效果（例如"去重 3 行"、"转换 23 格 · 失败 1"）。

对每一步，你只需要做三个判断之一：

| 判断 | 操作 |
|------|------|
| **认可推荐** | 什么都不用做，直接看下一步 |
| **部分调整** | 在右栏改（增删规则、改字段、改阈值…），改完预览与 SQL 立刻重算 |
| **这一步不需要** | 点步骤节点上的 `✕`，该步停用；流程链路自动跳过它并重算 |

每一步具体在配什么，见第三节。

### 第 4 步 · 处理唯一必须人工拍板的一项：日期歧义（右栏）

这是全页**唯一一处引擎拒绝替你决定**的地方，必须知道。

#### 先看「📅 参与标准化的字段」：这里只列**日期字段**

面板的这一节只列出**被标记为日期语义的列**（本例 `loan_date`、`return_date`），不会把 `loan_id`、
`reader_no`、`sync_time` 之类混进来。

> **为什么不能随手勾别的列**：日期标准化对每一格都做「解析成日期」的动作，解析不出来就置 NULL。
> 把 `reader_no`（值形如 `R20260012`）勾进来，它**每一格都解析不出日期 → 整列变 NULL**，
> 数据就这么没了。所以：面板不列非日期列；万一配置里残留了（旧版本存下来的配置），
> 面板会用黄色告警标出「配置里残留了 N 个非日期列」并给一个 **🧹 移除这些列** 按钮，
> 同时预览与生成的 SQL 都会自动跳过它们（SQL 头部会写明"已跳过、未写入 SQL"）。

到**日期标准化**这一步，右栏会出现一个警告区：

> **存在歧义格式，必须人工确认解释规则 · 待确认**
> `08-09-2026` 这类值既可解为「日-月-年」也可解为「月-日-年」，两种解释结果不同。
> 按 `DD-MM-YYYY` 解释（日在前）| 按 `MM-DD-YYYY` 解释（月在前）
> 当前 `08-09-2026` 归一为 `2026-09-08`

操作：

> ⚠ **默认口径就是「月在前 MM-DD-YYYY」（与 ISO 8601 一致），且不视为"待确认"**——
> 弹窗是「事后复核通道」而不是「必须拍板的阻塞入口」。如果你信任 ISO 标准，**直接保存即可**，不必走弹窗。
> 想看对比再决定，点「⚖ 打开歧义确认弹窗」即可。

1. 点 **「打开歧义确认弹窗」**（或右栏配置面板的「⚙ 修改口径」展开两个 radio）
2. **读两张口径卡片**。每张卡片的读法是
   「`口径 A/B` → 把原始值 `08-09-2026` 读作 ↓ → **归一结果**」——
   卡片里那个大号日期就是该口径下的实际结果（口径 A = `2026-09-08`、口径 B = `2026-08-09`），点卡片即切换
3. **看「🔎 自洽性自查（帮你选）」**。引擎用「业务日期不应晚于该行同步时间」这条硬约束给两个口径打分，
   并给出具体实例（哪一行、`sync_time` 是多少、两种口径分别得什么日期）。哪个口径"不成立"条数少，
   哪个与数据更自洽 —— 这只是**建议**，最终口径仍由你决定
4. **注意黄色提示「同一列可能混用了两种写法」**。若同一列里既有 `08-09-2026` 这类歧义值、
   又有 `13-08-2026` 这类只有一个可行解的值，说明**源系统可能两种写法混用** ——
   这时选任何单一口径都会把其中一部分解释错，应先回源核对（可对照同一行的 `sync_time` 等已知字段）。
   这是**数据本身**的问题，不是页面算错
5. 对照**冲突样本表**（两种口径结果不一致的取值 + 影响行数）→ 选定口径 → 确认

**不确认会怎样**：不是报错，而是① 流水线上"日期标准化"节点常驻一个**待确认**徽标；② 生成的 SQL 头部会打一行 `-- ⚠ 配置提示：日期字段 … 存在歧义格式 … 尚未人工确认`。确认后两处提示同步消失。

> 确认状态按"源表 + 歧义值集合"记忆，**同一份数据不会重复打扰你**；换表或数据变了才会再问。

#### ⚠ 这个口径管到哪：只裁决歧义值，不管唯一解

选完之后你会发现**有些日期没变**，这是对的，不是没生效：

| 值 | 为什么 | 选「日在前」 | 选「月在前」 |
|----|--------|-------------|-------------|
| `08-09-2026` | 8 和 9 都 ≤12，**两种解释都成立** | `2026-09-08` | `2026-08-09` |
| `13-08-2026` | 13 不可能是月份，**只有一个可行解** | `2026-08-13` | `2026-08-13`（不受影响） |
| `2026/08/01`、`20260804` | 格式本身无歧义 | 不变 | 不变 |

一句话：**口径是给"没法自动判断"的值用的，能自动判断的值不需要它拍板。**

面板上会直接标出这条规则的实测样例（「像 `13-08-2026` 这种只有一个可行解的…，选哪个口径都归一为 `2026-08-13`，不受影响」），对照着看就行。

> 若某个值在**两个口径下都不成立**（如 `32-13-2026`），才判为"无法解析"→ 置 NULL 并计入失败明细。

### 第 5 步 · 用预览验证（中栏）

预览区就是你的验收工具，三个用法：

| 用法 | 怎么做 | 看到什么 |
|------|--------|----------|
| **分步回放** | 点流水线上任意步骤节点 | 表头变为"回放至 · 该步"，显示该步执行后的结果 |
| **找变化的单元格** | 浅蓝底（`is-newval`）的格子 = 该步改动的值；鼠标悬停显示**原始值** | 一眼定位这一步动了什么 |
| **只看有变化的行** | 勾选右上角「仅看发生变化的单元格」 | 整行都没变化的行会被隐藏 |

> **预期行为提醒**：在「字段映射」这一步勾选该复选框，会得到一张空表——因为这一步只改**列名**、不改单元格取值，所有行都被判为"无变化"。页面会给出文字说明，属正常现象，取消勾选即可看完整产出。

> **「字段数 / 行数突然变了」的心智模型**：预览看到的列与行完全由 **预览回放点**（标题里的「回放至 · XXX」）决定。
> - 回放至 `码值映射`（第 3 步）= 8 列 · 12 行（关联、派生都还没发生；去重也还没发生）
> - 回放至 `质量校验`（最后一步）= 13 列 · 9 行（多出 4 列关联 + 1 列派生，行数被去重减少）
>
> 如果你点「停用此步」把**当前正在回放的那一步**停用，**回放点会自动挪到最后一个启用步骤**，避免预览画出一个不存在的中间态；同时会弹一个 ⚠ toast 「预览回放点已自动从『X』切到『Y』—— 原步骤已停用，挪到最后一个启用步骤才不会画出不存在的中间态」告知。
> 想要回到原步骤的视图：点一下「码值映射」节点即可。

### 第 6 步 · 处理失败行与质量门禁（右栏）

到这一步看两处：

**① 转换失败策略**（类型转换步骤）：三个选项，直接影响数据怎么写进 DWD。

| 选项 | 失败值怎么处理 |
|------|----------------|
| 置为 NULL（保留行） | 默认。保留行，失败值写 NULL，原始值仍留存在失败明细里 |
| 填默认值（保留行） | 保留行，失败值填你指定的默认值 |
| 丢弃该行 | 整行不写入目标表 |

**② 质量门禁**（质量校验步骤）：规则列表 = 规则类型 + 字段 + 阈值（通过率 %）+ **不达标动作**。动作三态是这个页面的"闸门"：

| 动作 | 含义 |
|------|------|
| **阻断** | 不达标即判定任务失败，**不写入目标表**并阻断下游（对应 DQC 强制规则） |
| 告警 | 只提示，仍写入 |
| 继续 | 仅记录，不影响写入 |

每条规则下方都显示**实测通过率**与违规行数。顶栏、目标节点、质量条、SQL 头部四处会联动显示门禁状态。

> **门禁真的会拦人**——实测：把「数据去重」步骤停用后，主键唯一性规则不达标，质量条立刻从"2 条规则告警"变成 **"门禁阻断写入"**。这就是验收时该演示的效果。

**③ 脏数据分流**（同一页签下方）：开启后，失败行会写入隔离表 `<目标表>_dirty`，带 `fail_field` / `fail_reason` / `fail_raw_value` / `quarantine_time` 四个审计列，并回写血缘（`_dirty → 质量看板 / 人工复洗队列 → 复核后回灌目标表`）。也可以随时点 **「导出失败行明细（CSV）」** 拿回去人工核查。

### 第 7 步 · 查看生成的 SQL（右栏页签 / 顶栏）

两条入口都行：顶栏 **「查看 SQL」**，或右栏切到 **「清洗 SQL」** 页签。

- 顶部下拉选**目标方言**：Hive 2.x/3.x、Spark SQL 3.x、MySQL 8.0、Doris 2.x —— 换方言会真实改写函数、日期格式串、正则算子、长度函数、调度变量写法
- **「复制」** 或 **「下载 .sql」**（文件名 = 任务代码.方言.sql）

生成的 SQL 分三段，照着顺序读：

```
① 质量门禁（DQC 断言）      ← 写入前先断言，不达标即失败
② 主写入 → <目标表>         ← 真正的 INSERT OVERWRITE/INTO
③ 脏数据分流 → <目标表>_dirty ← 失败行落隔离表（开启分流时才有）
```

SQL 头部是一段"自解释注释"，写明分层链路、列口径来源、调度变量、写入模式、关联的维表，以及所有的 ⚠ 配置提示/方言差异。

### 第 8 步 · 配任务与调度，然后保存（顶栏）

点 **「任务与版本」**：配任务代码、任务名称、责任人、源表、目标表、分区字段、写入模式（覆盖当日分区 / 追加写入）、`bizdate` 调度变量、调度周期（每日 / 每小时，cron 会真实换算）、失败重试次数、上游依赖。

> **这些字段全都真落进 SQL**：改目标表，SQL 的写入目标与隔离表名一起变；切"追加写入"，主表由 `INSERT OVERWRITE` 变 `INSERT INTO TABLE`；改分区字段，分区键跟着换。

点 **「保存清洗任务」** → 弹窗里会汇总本次配置（流水线步数、分层链路、产出列数、采样产出、质量分、失败格数）→ 确认保存。
同一个面板里还有**版本管理**：保存快照、看逐项 diff（按配置路径给出新增/删除/修改）、一键回滚并重算。

### 第 9 步 · 全量试跑（顶栏）

点 **「全量试跑」**：默认 20 万行，**上限 1,000,000 行**（超限直接拒绝，避免在开发/原型环境误触发大查询）。

试跑会按 12 行模板等比例生成数据、**真实跑完全部步骤**，给出全量口径的质量分、失败格数、脏数据行数。试跑期间预览表只渲染前 200 行，但**指标按全量统计**；跑完可以一键切回采样模式。

> 上线建议（页面里也写了）：**先对全量跑一次试跑并核对质量分，再挂每日调度**；质量分低于阈值应当阻断写入，而不是静默产出一张凑合的表。

### 第 10 步 · 多表批处理（顶栏，可选但很省事）

一套规则要套到多张同类源表时用。点顶栏 **「多表批处理」**：

1. 面板列出全部候选源表，并给出**同类判定**（"同类" / "缺 状态" 这类缺角色的提示）
2. 勾选要处理的表，或点「全选同类表」一次选中所有角色齐备的表
3. 两个适配开关：自动把目标表自己的**日期字段**纳入标准化、自动把**数值字段**纳入类型转换（目标类型由采样数据推断）
4. 点 **「开始批处理」**

结果面板逐表给出：输入行数 → 产出行数、去重消除行数、失败数、质量分、门禁状态、套用了几项规则；下面列出**不适用 / 需人工确认的规则明细**；最底部是**按表分段的合并 SQL**，可一次复制或下载。

两条重要保证：

- **同类判定看"语义角色"而不是表名像不像**。例如 `loan_id` 会自动翻译成目标表的 `renew_id` / `return_id` / `hold_id`（因为它们在各自表里都是"业务主键"这个角色）。
- **翻译不了的规则会被明确标注，不会静默丢弃**。尤其是"值形态专有"的规则（比如只认借阅流水号的正则 `^LN\d{11}$`、只认 `在借/已还` 的值域白名单），字段换名后判据不成立，会列为**需人工确认**让你自己决定。

> 批处理是**只读**的：跑完会把你当前的表、配置、流水线顺序原样还原，也不会污染撤销历史。

## 三、逐步骤速查表

| 步骤 | 这一步在干什么 | 你要确认的判断 |
|------|----------------|----------------|
| **01 字段映射** | 把源字段名改成 DWD 规范字段名，或排除不要的字段 | 是否要改名 / 排除；重名会被拒绝，改名后下游引用会自动跟着改 |
| **02 字段清理** | 全列去前后空格与制表符；把 `/`、`NULL`、`-`、`空` 等占位符归一为 NULL | 占位符清单是否符合这张源表的实际脏值 |
| **03 码值映射** | 枚举码翻译成业务可读值（`Y/N → 在借/已还`） | 值域是否完整；未匹配值要"保留原值/置 NULL/填默认值"。**一个字段只生效第一组**：字段下拉里已被其它块占用的源字段不会再出现；存量配置若出现同字段配了两组，第二组会**红底标注**并给「并入第 N 组」一键合并（预览与生成的 SQL 共用这条规则，两者永远一致） |
| **04 类型转换** | 字符串 → 数值类型（金额会自动剥离 `¥` 与千分位） | 哪些字段要转成什么类型；**转换失败策略**（置 NULL / 默认值 / 丢弃行） |
| **05 日期标准化** | 只处理**日期字段**，多格式统一成 `YYYY-MM-DD`，无法解析的置 NULL | **必须确认日期歧义口径**（唯一的强制人工项）；弹窗里的「自洽性自查」可帮你选 |
| **06 数据去重** | 按业务主键去重，保留同步时间最新/最早的一条 | 去重键选得对不对（选错会误删）；页面会给出等价 SQL 以便核对 |
| **07 多表关联** | LEFT / INNER JOIN DWD 维表与主档，把编码翻译成业务字段，拼出宽表 | 关联键、取哪些字段；命中率会实时显示（未命中行保留、字段为 NULL） |
| **08 列加工** | 派生新列：正则提取 / 按分隔符拆分 / 多列合并 | 提取正则是否匹配该字段的真实形态 |
| **09 数据脱敏** | 对证号、姓名等敏感字段做部分掩码 / 全掩码 / MD5 | **默认停用**。开启会真实改写写入 DWD 的值，须先确认下游 ADS 是否还需要原值 |
| **10 质量校验** | DQC 式规则（唯一性/非空/值域/区间/格式/自定义）+ 阈值 + 动作 | 阈值定多少、不达标是阻断还是告警；是否开启脏数据分流 |

> 「多表关联」只提供 LEFT / INNER 两种连接方式，这是**有意为之**：只有这两种能在"预览结果"和"生成 SQL"里保持完全一致的语义（右连接可以用交换左右表来表达）。

## 五、常见"看起来不对劲"的情况

| 现象 | 是不是问题 | 解释 / 怎么办 |
|------|-----------|---------------|
| 勾了「仅看发生变化的单元格」表格是空的 | 不是 | 这一步没有任何单元格取值变化（如"字段映射"只改列名）。页面有文字说明，取消勾选即可 |
| 质量条显示 **⛔ 门禁阻断写入** | 不是 | 某条 `阻断` 级规则未达阈值。去「质量校验」看是哪条、实测通过率多少 |
| 日期步骤挂着**待确认**徽标，SQL 头部也有 ⚠ | 不是 | 日期歧义还没人工拍板，见第 4 步 |
| 换了日期口径，但有些日期**一动不动** | 正常 | 那些值只有一个可行解（如 `13-08-2026`），不受口径影响，见第 4 步的对照表 |
| 质量条显示"采样 12 行 · 不代表全量" | 不是 | 提示你当前指标是采样口径。要全量口径请用「全量试跑」 |
| 预览里出现 NULL | 视情况 | 可能是空值归一的正常结果，也可能是转换失败。看质量条的"转换失败 N 格"，并在失败明细里核对原始值 |
| 某步节点是灰的、标着"已停用" | 正常 | 该步被 `✕` 关掉了，链路会跳过它。点 `✕` 可重新启用 |
| 改完配置后质量分变了 | 正常 | 全页是实时重算的，这正是它比"填完再提交"好用的地方 |
| 明明说已修好，界面还是老样子 | 先强刷 | 多半是浏览器缓存了旧的 `assets/*.js`。`npm run dev` 起的 dev server 已发 `Cache-Control: no-store`，正常情况下刷新即见；若用的是别的静态服务（如 `python3 -m http.server`），按 **⌘⇧R** 强制重新加载 |
| 「日期标准化」里找不到 `reader_no` / `loan_id` 了 | 不是 | 这一节**只列日期字段**（按语义角色筛过）。非日期列不该参与日期归一，见第 4 步 |
| 日期步骤出现黄色「配置里残留了 N 个非日期列」 | 是提醒 | 旧配置留下的脏项，已自动跳过（预览与 SQL 都不生效）。点 **🧹 移除这些列** 清掉即可 |
| 点左栏卡片 / 顶栏面包屑表名没反应 | 先强刷 | 切换源表浮层应贴在**被点的那个元素**下方展开（空间不够会自动翻到上方，所以从面包屑点开会出现在顶栏正下方）。浮层没出来多半是浏览器还在跑旧的 `cleaning.js` / `src-picker.js`，按 **⌘⇧R** 即可 |
| 顶栏那个「切换源表」按钮去哪了 | 设计如此 | 它和左栏卡片、面包屑表名是三处同功能入口，而它离操作对象（当前源表）最远 —— 对象在左上角、入口在右上角第 9 个位置。已下线，切表统一走**面包屑表名**或**左栏卡片**，快捷键仍是 `⇧⌘K` |
| 浮层里搜不到想找的表 | 换个关键词 | 搜索同时匹配 **表名 / 中文名 / 数据源名 / 源端表名 / 目标表 / 字段名**。搜 `reader_id` 会列出所有含这个字段的表；搜 `ALEPH` 会列出该数据源下全部表；搜 `holding` 会找到源端表名里带 holding 的那张 |
| 浮层里某张表标了「缺 状态」 | 注意 | 当前模板里有步骤用到了「状态」角色（如码值映射），而该表没有这类字段。切过去后这些规则会被显式标成**不适用**（不会静默丢弃），高亮行会在**切换之前**就预告有几项 |
| 浮层里某张表标着灰色的「未配清洗任务」 | 不是故障 | 这张表**已在 ODS 同步**，但还没为它建清洗任务（数据源刚接入时就是这个状态）。点它**不会切过去**，只会告诉你去「数据源管理 → 库表结构」或「ODS 数据表」建任务 —— 这是**故意的**：假装切过去会让你看到一张其实没有任何规则的"当前表"，比不切更容易误导 |
| 从「数据源管理 / ODS 数据表」点「去清洗」，落下来却是另一张表 | 老问题，已修 | 以前这个入口没带表身份，落下来永远是默认表。现在点了会带 `?table=<ods_id>` 跳过来：已配清洗任务 → **直接切到那张表**；还没配 → 停在默认表 + 一条提示，不会静默落到别的表上 |
| 切表后原来配好的规则去哪了 | 不会丢 | 每张表各自缓存自己的配置：切走时存下、切回时原样恢复。第一次切到的表会用模板自动适配，并告知适配了几项 |
| 点「停用此步」后预览字段变多 / 变了 | 正常 + 有提示 | 预览回放点**只能落在已启用的步骤上**，停用「正在回放的那一步」时会自动挪到最后一个启用步骤；会出 ⚠ toast 「预览回放点已自动从『XXX』切到『YYY』」。点一下原步骤节点即可让回放回到那一步 |
| 弹窗里两个日期看不出哪个属于哪个口径 | — | 卡片读法固定为「口径 A/B → 把原始值 X 读作 ↓ → 结果」，且卡片标题就是口径本身 |
| 弹窗说两个口径各有几条"不成立" | 不是 | 这是「自洽性自查」：用"业务日期不应晚于同步时间"给你一个客观参照，最终仍由你定 |
| 套用了不合适的模板，能反悔吗 | 能 | 套用是一次普通操作，已登记进撤销栈 —— 顶栏「↶ 撤销」或 `⌘Z` 直接回到**套用前的完整配置**（含你手工调过的每一项）。注意撤销栈是按操作顺序回退的：套用之后又做了别的改动，要先撤掉那些 |
| 规则模板库里的模板能新增 / 编辑吗 | 暂时不能 | 原型内置 **3 套**模板（通用借阅流水清洗 / 读者主数据清洗 / 金额·日期轻度清洗），目前只支持「浏览 + 套用」。**新增 / 编辑 / 删除模板**尚未实现 —— 这里是已知的能力缺口，如实标注，不放假的入口 |
| 弹窗提示"同一列可能混用了两种写法" | 注意 | 说明源数据自身可能不一致（既有歧义值又有唯一解值），选任何单一口径都会错一部分，**需回源核对** |

## 六、这一页的边界（原型阶段说明）

避免误用，这几条必须知道：

1. **预览与指标基于 12 行采样**，不是真实查库；全量试跑是**按模板等比例放大生成**的数据，不是真的去查那 128 万行。
2. **配置不落服务端**：保存/版本走浏览器本地存储，刷新页面仍在，但不是真实的任务发布。
3. **生成的 SQL 是真的**，可直接拿去 Hive/Spark/MySQL/Doris 执行——这是这一页最"实"的产出。
4. 规则引擎是**真实的**：每一步的预览都是按配置逐格算出来的，不是预置动画。所以任何配置写错你都能立刻在预览和质量分上看出来。
5. **有真实规则模板的只有 10 张表**。切换器里能看到全部 **29 张 ODS 表**（与「数据源管理 / ODS 数据表」同一份注册表），但其中 19 张还没配清洗任务 —— 它们标着灰色的「未配清洗任务」，点了**不切表**。这不是缺页，而是如实反映"源已接入、清洗任务尚未建立"的中间状态；这也正是「数据源管理」页里那张表的「去清洗」会先把你引到"建任务"的原因。
