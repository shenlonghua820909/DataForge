# 数据集成模块 · 操作手册（原型版）

> 覆盖 `02b-data-sources.html`（数据源管理）与 `02c-ods-tables.html`（ODS 数据表）两页。
> 原型没有后端，所有「解析 / 同步」都在浏览器里做真实计算，写入 `localStorage` 做状态持久化。

---

## 一、先建立心智模型：数据集成是「三段式」

```
   源端                     集成层（本模块）                    数仓
┌─────────┐        ┌──────────────────────────┐        ┌──────────────┐
│ 业务库   │        │ ① 数据源（连接从哪来）    │        │ ODS 原始数据层 │
│ 文件     │ ─────► │ ② 同步任务（搬什么过来）  │ ─────► │ DWD 明细层     │
│ 接口     │        │ ③ ODS 表（搬过来了什么）  │        │ DWT / ADS      │
└─────────┘        └──────────────────────────┘        └──────────────┘
```

- **数据源**回答：连谁、连得上吗、谁负责。
- **同步任务**回答：**搬什么、怎么搬、多久搬一次**。它是「源端表」和「ODS 表」之间那个**可配置、可调度、可重跑**的载体 —— 一条任务可以带一张表（精细），也可以带 N 张表（整库批量）。
- **ODS 表**回答：**到底搬过来了哪些表、还有哪些没搬**。← 这才是老板/客户真正会追问的层。
- 所以这两个页面不是重复的：02b 是「按源看」，02c 是「按表看」。

**三者是 1 : N : N 的关系**：一个数据源下挂 N 条同步任务，一条任务下带 N 张源端表，每张落成一张 ODS 表。所以「ODS 表数」和「同步任务数」不是一回事 —— 建一条「整库同步」任务就会一次多出好几张 ODS 表。

## 二、02b 数据源管理

### 1. 新增数据源（含 Excel / CSV 拖拽解析）

`新增数据源` → 第 1 步选类型 → 第 2 步：

| 类型 | 第 2 步长什么样 |
|---|---|
| 库 / 消息队列 / 接口 | 主机、端口、库名、账号密码 |
| **Excel / CSV / JSON** | **拖拽上传区**（本地解析）+ 可选的服务端路径 |

拖拽区支持：
- **拖文件进来**，或点一下选文件；也支持「载入示例文件」——没有现成文件时也能看到完整解析结果。
- 解析在**浏览器本地**完成（`assets/file-parse.js`，零依赖）：
  - `CSV / TSV / TXT`：编码嗅探（BOM → UTF-8 → GBK 回退）+ 分隔符嗅探（`,` `\t` `;` `|`）
  - `XLSX / XLSM`：自解 ZIP 中央目录 → `DecompressionStream('deflate-raw')` 解压 → 读 `sharedStrings.xml` 与工作表 XML
  - `JSON`：对象数组按键并集展平成二维表
  - `XLS`（BIFF8 旧二进制）：**无法纯前端可靠解析，明确降级提示**，不假装成功
- 解析结果给出：文件名/大小/工作表/编码 → **行数 · 字段数 · 空值率** → **推断主键 · 日期列** → 字段清单（类型 / 非空率 / 样例值 / 备注）→ 前 8 行预览。

第 3 步对文件类是**「校验解析结果」**而不是「测网络」，逐项给结论（表头识别、类型推断、主键唯一性、空值率、编码、可映射字段）。

> ⚠ 边界：类型推断只看「值形态 + 表头语义」，不做业务口径校验；口径归清洗页管。

### 2. 删除数据源

- 卡片右下角 hover 出现 `✎ 编辑` / `🗑 删除`；列表视图行尾同款按钮；详情抽屉右上角也有 `删除`。
- 删除前弹**二次确认**，列清影响面：该数据源名下有几张 ODS 表、几张待同步会被一并摘除。
- 删除后底部出现**撤销条（约 8 秒）**，可一键恢复。

### 3. 看「库里一共几张表、同步了几张」

数据里有**两个不同的分母**，界面上分得很清楚：

| 口径 | 含义 | 在哪看 |
|------|------|--------|
| **源端库表** | 这个数据库 / 湖仓里**实际存在**的表 | 卡片角标、列表「ODS 表」列、抽屉「库表结构」概览第一格 |
| **已纳管 ODS 表** | 平台上**已经建了同步任务**的表（含"任务建了、数据还没落"的未同步表） | 抽屉「同步任务」页签、02c 全表视图 |

- **卡片角标**：`已同步 6 / 源端 12 张 · 还有 6 张没同步`，进度条按 绿(已同步) / 黄(已建任务待同步) / 灰(尚未纳管) 三段着色。
- **列表视图**：「ODS 表」列（副标题写明分母是**源端**）显示 `6/12`。
- **详情抽屉 → 库表结构**页签：
  - 顶部四联概览 —— **源端库表 12 / 已同步到 ODS 6 / 已建任务待同步 3 / 尚未纳管 3**；
  - 左侧是源端的**全部**表，按「已同步 → 待同步 → 尚未纳管」排序，虚线框 = 还没纳管；
  - 点任意一行，右侧给出这张表的落地情况（源端位置、行数、字段数、ODS 表名、调度、最近同步、质量分、落库目标）；
  - 未纳管的表给「**纳入同步清单**」按钮 —— 点一下它就从"尚未纳管"挪到"已建任务待同步"，并立刻出现在 02c 里，可以继续同步与清洗。
- 详情抽屉 → **同步任务**页签：顶部是四档 ODS 落地情况（已同步 / 同步中 / 未同步 / 失败待确认），下面是**这个数据源的任务列表** —— 每条任务显示名称、运行态（未运行 / 运行中 / 运行成功 / 运行失败）、标签（已暂停 / 阻塞类型 / 批量 N 张表）、`来源 → 目标`、调度、映射字段数，以及最近一次运行（时间、写入行数、脏数据条数、耗时；失败则直接给出原因）。
- 每条任务带四个动作：**运行 / 详情 / 暂停·启用 / 删除**；页头还有「新建同步任务」与「运行全部已启用任务（N）」。
  详见下面第 4、5、6 小节。
- 顶部还有「同步全部未同步表（N）」与「在 ODS 全表视图中查看 →」。

> ⚠ 文件 / API / 协议类数据源**没有**「源端库表」这一层（结构来自文件或端点本身），卡片只报 ODS 表数，不硬凑分母。

### 4. 新建同步任务（5 步向导）

入口有三处，都是同一个向导：抽屉「同步任务」页签的「**新建同步任务**」、空态里的同名按钮、以及数据源向导**完成页**的「立即创建同步任务」——刚建完数据源就能顺手把任务配好。

| 步骤 | 这一屏要你做什么 | 做错了会怎样 |
|---|---|---|
| ① 选择源表 | 勾选要搬的源端表，可多选（多选 = 一条批量任务）。上面有「**整库同步（全选 N）**」「全选尚未纳管（N）」「清空」三个快捷键 | 一张表只能属于一条任务 —— 已经被别的任务占用的行会置灰、勾不上，并标「已建任务」 |
| ② 目标表 | 目标 ODS 表名，默认按 `ods_<源表>` 规则自动生成，可逐张改 | 名字必须 `ods_` 开头、只含小写字母/数字/下划线；**非法或与同批其它表重名**都会被拦住不放行，并把那一行标红 |
| ③ 字段映射 | 逐列配：是否同步 / 目标字段名 / 目标类型 / 默认值。上面有「**全选字段 / 按名匹配（重置）/ 全部不同步**」 | 「类型校验」列会实时给结论：`一致` / `注意`（如数值→字符串）/ **`冲突`**（如文本→数值，整行标红）。至少要留一个字段，否则不放行 |
| ④ 同步策略 | 抽取方式（**全量覆盖** / **增量追加**）+ 写入模式（overwrite / append / upsert）+ 脏数据阈值 + 并发数 | 选了「增量追加」但没指定增量字段 → 拦住（没有水位字段就会整表重跑） |
| ⑤ 调度配置 | 任务名称 + 周期（实时 / 分钟 / 小时 / 每天 / 每周 / 每月 / **手动**）+ 调度时刻 + 确认摘要 | 任务名为空 → 拦住，不会造出一条无名任务 |

点「创建任务」后：向导关闭 → **自动跳到该数据源的「同步任务」页签**，新任务带一圈高亮脉冲，直接能看到。
如果第 ① 步里选了「尚未纳管」的源端表，创建任务时它们会**一起纳入 ODS**（即：任务一建，ODS 层就多了这几张表，状态是「未同步」）。

> ⚠ 第 ③ 步的源端字段：**文件类数据源**用真实的文件解析结果（会写明来自哪个文件）；**库表类**没有真实元数据，用的是与源端表字段数一致的**示例字段**，页面上有黄底提示「⚠ 这里的源端字段是示例字段」明确标出 —— 不冒充真 schema。字段清单要等任务创建后由元数据采集拉取。

### 5. 任务列表上的四个动作

| 动作 | 会发生什么 |
|---|---|
| **运行** | 立刻跑一次，产生一条运行实例：`运行中（蓝）→ 运行成功（绿）/ 运行失败（红）`，同时把所辖 ODS 表的状态一起改掉（成功 → 已同步；失败 → 失败；结构变更 → 结构变更） |
| **详情** | 打开任务详情弹窗：任务配置（调度状态 / 并发与脏数据阈值 / 同步策略 / 运行环境）、**表映射**、**字段映射**（带类型校验结论）、**运行实例**（开始时间 / 状态 / 耗时 / 写入行数 / 脏数据 / 失败原因）。左上角「立即运行」也可以在这里跑 |
| **暂停 / 启用** | 暂停只停**调度**，手动「运行」不受影响；再点一次恢复 |
| **删除** | 二次确认，明确告诉你**已落地的 ODS 数据不会被物理删除**，只是失去同步来源（那张表在 ODS 列表里会变成「未建任务」）。删掉的任务不会被自动重建 |

**失败是怎么发生的（原型里怎么复现）**：失败**不靠随机**，而是由任务上的「阻塞项」决定 —— 种子里固定有 4 条任务是阻塞态，分三类：

| 阻塞类型 | 表现 |
|---|---|
| 解析失败 | 源文件表头缺失，抽不出来 |
| 鉴权失败 | 库账号无权限 / 凭据过期 |
| 结构变更 | 源端表结构变了，与已落地的 ODS 表对不上 |

点「运行」→ 实例变成**失败**并写明原因 → 任务详情里出现红色横幅和「**处理阻塞**」按钮 → 点它 → 再「运行」→ **成功**。这是一条完整的 `失败 → 看原因 → 处理 → 重试 → 成功` 闭环。（解析 / 鉴权类连跑失败还会把调度**自动暂停**。）

### 6. 运行监控页签

三个 KPI（近 7 天运行次数 / 成功率 / 写入总行数）+ 近 7 天写入量柱状图 + 事件流。

**这三块全部由任务的运行实例派生**，同一份数据的三个视图 —— 你在「同步任务」里跑一次任务，这个页签立刻跟着变（不再是一段与实际状态无关的演示文字）。

## 三、02c ODS 数据表（全表视图）

回答三个问题：**有哪些表？分别来自哪个数据源？哪些还没同步过来、要不要同步？**

- **KPI 四联**：ODS 表总数 / 已同步 / 未同步 / 异常待处理 —— **点 KPI 即筛选**。
- **筛选**：关键字（表名、中文名、源表、数据源）、数据源、业务域、状态。
- **两种视图**：
  - `按表`：一行一张表，列含 表名 / 中文名 / 来源数据源 / 业务域 / 源表 / 行数 / 字段 / 状态 / 最后同步。
  - `按数据源`：一张卡片一个数据源，卡头写「ODS N 张 · 已同步 X · 未同步 Y」，展开是它名下的表。
- **未同步的表**底色高亮，行尾给 `同步` 按钮；勾选多张后底部出现批量操作条 → **批量同步**。
- 同步过程：`未同步 → 同步中（黄点闪烁）→ 已同步`（并补齐行数、质量分、最后同步时间）。
- 点任意一行打开**表详情抽屉**：源端定位（库.表）、调度、目标 DWD 表、**负责这张表的同步任务与它最近一次运行实例**、字段清单、同步时间线，以及「**去清洗**」。
- 若这张表名下还没有任务，抽屉里会给一条黄色提示，而不是假装它有调度。
- 点「**去清洗**」会**带着这张表的身份**跳到清洗页（`15-data-cleaning.html?table=<ods_id>`）：这张表已配清洗任务 → **直接切到那张表**；还没配 → 停在默认表并弹一条提示，告诉你去哪建任务。**不会再出现"点了去清洗、落下来却是另一张表"**。（02b 的抽屉与列表里的「去清洗」同理。）

## 四、常见疑问

**Q：为什么 02b 和 02c 都要有「同步」按钮？**
A：02b 是**按源批量**（这个数据源下的表一起处理），02c 是**按表精准**（只想补某一张）。两处落的是同一份注册表（`assets/integration-data.js`），状态天然一致。

**Q：卡片写「已同步 1 / 源端 7 张」，到底哪个才是"表的总数"？**
A：两个都是，只是分母不同 —— **源端库表**是那个库里**实际存在**的表（7 张），**已同步**是数据真的抽到 ODS 层的表（1 张）。中间还有第三种状态：**已建任务待同步**（任务建好了、数据还没落）。集合关系是「源端库表 ⊇ 已纳管的源端表 ⊇ 已同步源表」；而「已纳管 ODS 表数」有时会**多于**已纳管的源端表数，因为同一张源端表可以挂多条同步任务（例如源端字段变更后会新建一条结构变更任务）。哪个数字该用哪个口径，第二节第 3 小节有对照表。

**Q：「同步任务数」和「ODS 表数」为什么对不上？**
A：它们不是一回事。一条任务可以带 N 张源端表（批量 / 整库同步），所以任务数 ≤ ODS 表数；反过来，删掉任务不会删表，于是又会出现「有表没任务」的孤儿表（在列表里显示「未建任务」）。界面上两个数字都标了各自的口径，别混着看。

**Q：刷新页面后我点过的同步会丢吗？**
A：不会。手动同步过的表会写进 `localStorage`（key `df_ods_overrides`）。想回到初始状态，清掉该 key 即可。

**Q：未同步的表是怎么发现的？**
A：真实系统里靠**源端元数据采集**（连库后 `SHOW TABLES` / 文件目录扫描）与 ODS 实际存在的表做差集。原型里由注册表的 `status: 'pending'` 直接表达。

**Q：Excel 拖进去解析，我的文件传到哪了？**
A：**哪都没传。** 全程 `FileReader` + `DecompressionStream` 在浏览器内存里完成。

**Q：点「去清洗」跳过去后，为什么清洗页左栏能选 29 张表、但真正有规则模板的只有 10 张？**
A：因为左栏的候选列表**跟这里的 ODS 注册表是同一份**（`assets/integration-data.js` 的 `ODS_TABLES`，29 张 / 12 个数据源）。已同步到 ODS 的表都会列出来，其中没建清洗任务的标着灰色虚线徽标「**未配清洗任务**」、点了**不切表**，只提示你先去建任务。这是**故意的取舍**：把这 19 张藏起来会让人以为"这些表白同步了"；把它们做成随意可点又会造成**假切换**（切到一张其实没有任何规则的"当前表"，用户以为自己配好了）。已配清洗任务的 10 张正常切换，并带「同类 / 缺 X」的角色齐备度徽标。

## 五、原型的边界（别当成缺陷）

1. 同步是**前端模拟推进**，没有真实调度与并发队列。
2. 解析只取前 5000 行做类型推断、前 8 行做预览，不做全量校验。
3. `.xls` 旧二进制格式不解，明确降级。
4. 「结构变更（schema）」是**阻塞项驱动的闭环**（可点「处理阻塞」后重跑成功），但字段级的 diff 明细是预置样例，没有真的去比对新旧结构。
5. 任务里库表类数据源的**源端字段是示例字段**（页面上已用黄底提示标出）；要变成真实字段需要接入元数据采集。
6. 调度是配置项的可视化承载，没有真实 cron / 资源组队列；实例的耗时与行数由任务体量和字段数派生。
