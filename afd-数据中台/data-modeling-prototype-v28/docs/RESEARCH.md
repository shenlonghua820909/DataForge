## 一、阿里云 DataWorks 智能数据建模

### 1.1 产品定位
阿里云一站式大数据开发治理平台 DataWorks 的核心模块，沉淀阿里巴巴数据中台建模方法论（OneData）。

### 1.2 四大核心模块

| 模块 | 职责 | 关键产出 |
|------|------|---------|
| **数仓规划** | 定义分层、域、业务过程 | 4层架构（ODS/DWD/DWT/ADS） + 业务总线矩阵 |
| **数据标准** | 字段标准、命名规范 | std_* 标准库 |
| **维度建模** | Kimball 理论建模 | 概念/逻辑/物理三层模型 |
| **数据指标** | 统一业务口径 | 原子/派生/衍生指标 |

### 1.3 维度建模：概念 → 逻辑 → 物理

**概念模型层**：
- 维度（Dimension）：业务观察视角
- 业务过程：可度量的业务事件

**逻辑模型层**：
- 维度表：包含维度及其属性
- 明细表：业务过程对应的可度量数据
- 汇总表：相同维度/周期的多个派生指标
- 应用表：面向具体业务场景

**物理模型层**：
- 物化到具体计算引擎（MaxCompute / Hologres / EMR Hive）
- 逆向建模：从物理表反向生成逻辑模型

### 1.4 关键功能

- **关系图画布**：可视化 ER 图，支持拖拽、连线、便签、分组
- **指标体系**：原子指标 + 派生指标 + 衍生指标
- **行业模型库**：零售电商、金融等行业模型一键导入
- **版本管理**：每次提交生成新版本，支持对比、回滚
- **DDL 自动生成**：模型 → MaxCompute / Hologres DDL
- **ETL 框架生成**：模型 → 同步任务 SQL 框架
- **数据标准绑定**：字段关联 std_* 标准，实现引标落标
- **质量规则自动生成**：发布模型自动生成数据质量监控规则

### 1.5 关键交互模式

- 三栏布局：左侧目录树 + 中间列表 + 右侧详情
- 顶部 Tab：维度建模 / 关系图 / 模型列表切换
- 字段编辑器：可视化字段管理，支持主键/外键/度量/冗余
- 批量建模：模板导入、批量创建
- 协同设计：多人同时编辑模型

## 二、字节火山引擎 DataLeap / DataFinder

### 2.1 产品定位
火山引擎数智平台（VeDI）的核心，强调"数据飞轮"和"以数据消费驱动数据生产"。

### 2.2 产品矩阵

| 产品 | 定位 |
|------|------|
| **DataLeap** | 一站式数据中台套件（敏捷研发、分布自治） |
| **DataFinder** | 增长分析 / 用户行为分析 |
| **DataWind** | 自助式 BI 平台 |
| **Data Catalog** | 元数据管理 / 数据地图 |
| **ByteHouse** | 高性能 OLAP 引擎（基于 ClickHouse） |
| **Data Agent** | 企业数据智能体（基于大模型） |

### 2.3 DataLeap 核心能力

- **数据集成**：异构数据源高速同步
- **数据开发**：批流一体任务编排
- **数据治理**：资产地图 / 血缘 / 质量
- **数据服务**：API 化数据消费
- **数据安全**：分级分类 / 脱敏

### 2.4 DataWind 可视化建模

- 轻量级 ETL 工具
- 实时任务支持配置高级参数
- 任务监控通知到飞书群
- 可视化查询、趋势分析表、迷你图、指标趋势图
- 嵌入式分析、Open API

### 2.5 Data Catalog 数据地图

- 2021 年 9 月随 DataLeap 首发
- 支持 EMR Hive 等多种数据源
- 元数据自动采集
- 字段级血缘

### 2.6 ByteHouse 实时数仓架构

**四层架构**：
```
ODS  贴源层
 ↓
DWD  明细层（维度建模 · Kimball）
 ↓
DWS  汇总层（跨域汇总）
 ↓
APP  应用层（ByteHouse 提供数据服务）
```

**核心引擎**：
- HaKafka：Kafka 数据源接入引擎
- HaUniqueMergeTree：基于主键更新数据的表引擎
- 自研 CBO 优化器：基于 Cascade 搜索框架 + Histogram 代价估算

### 2.7 业务实践
- 抖音、头条等内部业务已成熟应用
- A/B 测试是字节"信仰"
- 强调"以应用为中心的数据中台"
- 推行"数据飞轮"：数据消费 → 业务决策 → 数据生产

## 三、关键方法论沉淀

### 3.1 OneData 指标体系（阿里）

**核心**：统一业务口径，告别"同名不同义"

**三层架构**：

```
┌─────────────────────────────────┐
│  原子指标 (Atomic Metric)        │  不可再拆解
│  = 业务过程 + 度量 + 聚合逻辑     │  例: 订单金额 SUM
└──────────────┬──────────────────┘
               ↓ + 时间周期 + 修饰词 + 维度
┌─────────────────────────────────┐
│  派生指标 (Derived Metric)        │  业务常用
│  例: GMV_每日 / 订单数_近7日     │
└──────────────┬──────────────────┘
               ↓ + 多派生运算
┌─────────────────────────────────┐
│  衍生指标 (Compound Metric)      │  比率/比例
│  例: 优惠率 = 优惠金额 / 订单金额 │
└─────────────────────────────────┘
```

### 3.2 Kimball 维度建模

**四步法**：
1. 选择业务过程
2. 声明粒度
3. 确认维度
4. 确定事实

**三种事实表**：
- **事务事实表**：每笔业务事件（最细粒度）
- **周期快照事实表**：固定时间间隔的状态（如每日库存）
- **累积快照事实表**：业务全生命周期的多个时间点（如订单从下单到签收）

**三种模式**：
- 星型模型：事实表 + 多个维度表（最常用）
- 雪花模型：维度表进一步规范化
- 星座模型：多个事实表共享维度（最常见于大型数仓）

### 3.3 数仓分层理论

业界常见有 5 层 / 4 层 / 3 层几种切法，差别主要在「维度表放哪一层、汇总层叫什么」。

**本项目采用 4 层口径（ODS / DWD / DWT / ADS）**：
| 层级 | 命名 | 职责 | 数据粒度 |
|------|------|------|---------|
| 1 | ODS | 原始数据层 | 原始数据、保持原貌 |
| 2 | DWD | 明细层（含宽表 + 维度/主档） | 业务过程事实、实体主档 |
| 3 | DWT | 主题汇总层 | 跨域多表关联后单独生成的汇总 |
| 4 | ADS | 应用层 | 业务场景 |

**对照：常见 5 层口径**（DIM 独立成层、汇总层称 DWS）：
| 层级 | 命名 | 职责 |
|------|------|------|
| 1 | ODS | 贴源层 |
| 2 | DIM | 维度层（业务实体） |
| 3 | DWD | 明细层（业务过程） |
| 4 | DWS | 汇总层（跨域聚合） |
| 5 | ADS | 应用层 |

本项目把 DIM 并入 DWD（维度表与主档表以 `dwd_` 前缀标识），并把 DWS 更名为 DWT，以强调「主题汇总」是由 ODS/DWD 多表关联后单独生成的一张宽表这一业务属性。

**3 层简版**（适用于小团队）：
- ODS + DW + ADS

## 四、设计启发

### 4.1 借鉴点

| 来源 | 借鉴 |
|------|------|
| 阿里 DataWorks | 三栏布局、字段编辑器、版本对比、模型库 |
| 阿里 OneData | 指标三层架构（原子/派生/衍生） |
| 阿里 Kimball | 维度建模四步法 |
| 字节 DataLeap | 轻量 ETL、场景模板 |
| 字节 ByteHouse | 实时数仓 4 层（ODS/DWD/DWS/APP） |
| 字节 DataWind | 可视化建模、指标趋势图 |

### 4.2 差异化创新

| 维度 | 大厂现状 | DataForge 创新 |
|------|---------|---------------|
| 视觉风格 | 偏传统 B 端 | 现代 SaaS、Notion-like |
| 业务语义 | 偏技术 | 业务口径 vs 技术口径分离 |
| AI 能力 | 初步集成 | 全流程 AI 助手 |
| 协同 | 简单 | 强协同 + 审计 + 消息 |
| 移动端 | 较弱 | 响应式 + 移动端适配 |

### 4.3 业务差异点

- **金融行业**：更强调合规、审计、脱敏
- **零售电商**：更强调场景化（直播、私域、会员）
- **互联网**：更强调实时、A/B 实验、用户行为
- **制造**：更强调 IoT、设备数据
